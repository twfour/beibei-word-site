# 开发日志

| 阶段 | 完成内容 | 代表性问题与解决办法 |
|---|---|---|
| 1 原型 | 首页、路线、六站框架 | 先建立移动端信息结构，再填充内容 |
| 2 内容 | 六站史实、因果链、关键词、30题 | 权威来源逐站标注，避免无出处材料 |
| 3 任务 | 六种智力任务、星级评分与顺序解锁 | 用因果排序、推理、拼图、计算、数独、配对表达不同历史选择 |
| 4 完整性 | 长征全景、四支队伍、会师关系、数字海报 | 明确六站不等于全部长征路线，并标注数据统计口径 |
| 5 史料 | 人物群像和史料阅读卡 | 不虚构引语，以简明转述配原始链接 |
| 6 趣味 | 行军指标、随机情境、选择后果 | 不用失败惩罚消解历史严肃性 |
| 7 成长 | 盖章、精神徽章、精神行囊、挑战奖章 | 让站点任务、星级与最终荣誉形成学习闭环 |
| 8 路线 | 红线与六双逐渐磨损的草鞋站标 | 用草鞋变化表现长征路越走越艰难 |
| 9 适配 | 修复路线文字越界、遮挡和站点定位 | 边缘站点内向展开，保持红线和站标清楚 |
| 10 交付 | 答辩模式、版本说明、测试清单和迁移清单 | 明确Web原型与AIA/APK成品的边界 |

每次修改后均进行 JavaScript 语法检查、浏览器渲染检查、线上资源核对和 Git 版本提交。
